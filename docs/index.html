轻量架构与传统方案对比

为什么选择原生 Bun + SQLite 单体架构？

对比维度 Material Vault (Bun + SQLite) 传统重量级知识库 / Notion 类
内存占用 (RAM) ~15 MB (极轻常驻) 500 MB ~ 2 GB (Electron / 重型 JVM)
数据所有权与格式 本地 SQLite + 原生 Markdown + SHA256 资产池 私有云端格式 / 难以完整离线备份

容器镜像体积 < 100 MB (多阶段 Alpine 极速分发) 800 MB ~ 2.5 GB (多容器依赖编排)

开箱即用 · 快速部署

支持 Docker 一键启动或本地极速源码运行。

方案 A：Docker Compose 部署 (推荐)

拉取 GHCR 官方多架构镜像（支持 x86_64 与 ARM64/NAS），一键常驻运行： 

# 1. 启动容器 (可在 compose 文件中配置 AUTH_PASSWORD)
docker compose up -d

# 2. 访问服务
http://localhost:3000
方案 B：Bun 本地开发与运行

克隆源码后毫秒级热重载启动： 

# 1. 安装与构建
bun install
bun run build

# 2. 启动生产服务 (可选 AUTH_PASSWORD 预设密码)
AUTH_PASSWORD=your_password bun start
⚙️ 环境变量与访问密钥配置 (Environment Variables)

Material Vault 支持通过环境变量预设访问控制与端口，特别适合 Docker 容器化编排或自动化部署环境：

环境变量 默认值 配置说明
AUTH_PASSWORD （留空） 访问保护主密码。若配置该变量，系统启动即强制启用登录验证；若留空，首次访问网页时可直接进行密码初始化。
PORT 3000 HTTP 服务监听端口。
NODE_ENV development 运行环境标识 (production / development)。
